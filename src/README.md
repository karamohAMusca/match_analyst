# `src/` — what each file does

```
corpus/*.md ──► corpus/cards.py ──► corpus/chunking.py ──► rag/ingest.py ──► Qdrant
  (cards)        read cards          one chunk per ##       embed + store     (Docker)
                                                                                 │
user question ──► agent/analyst_agent.py ──► tools/corpus_tools.py ──► rag/retrieval.py
                  (Agent + prompts.py)        search_cards, read_card    Retriever ◄─────┘
                                                                 (dense + BM25 → fusion → max 1 per card)
guardrails around the agent:
  question ──► guardrails/input_guard.py ──(football only)──► agent ──► guardrails/output_guard.py ──► answer
               off-topic, injection: fixed reply, no model call        language, names/numbers, citations:
                                                                       on a problem, one rewrite
```

| File | What it does | Needs |
|---|---|---|
| `core/config.py` | Project paths and settings from `.env` (models, Qdrant host/port/collection); `LLM_PROVIDER`, the provider datapizza's `ClientFactory` builds the agent's client for (OpenAI). The API key is read only by `require_api_key(provider)` (`<PROVIDER>_API_KEY`), right before a call. | — |
| `core/disk_cache.py` | `DiskCache`: datapizza's `Cache` interface saved as a JSON file in `.cache/`, so what was paid for once is read back after a restart. Given to the judge's client (datapizza looks every call up before asking the model: a re-judge stopped halfway does not pay again) and used by `CachedEmbedder`. Typed answers are rebuilt with their class; each new value is saved at once, so a run stopped halfway keeps what it paid for. | — |
| `corpus/cards.py` | Reads a card: YAML front matter → `metadata`, Markdown → `body`. Loads all cards or only those in `manifest.json`; `stale_cards()` tells which cards changed since the last manifest build. | — |
| `corpus/chunking.py` | Splits a card into chunks, one per `##` section, each starting with the card title. Front matter goes into the chunk payload, not into the text. Fixed chunk ids (no duplicates on re-ingestion). | — |
| `rag/store.py` | Connects to Qdrant (Docker), creates the collection, builds the OpenAI embedder. `search_vector()` is the dense search: nearest chunks with their similarity score, optionally only from some card categories. | Docker, key |
| `rag/ingest.py` | `sync_corpus()`: puts the cards into Qdrant with a datapizza `IngestionPipeline`. Incremental: embeds only new or changed cards, removes deleted ones. | Docker, key |
| `rag/retrieval.py` | `Retriever`: the search used by the app. Hybrid: dense (Qdrant) + BM25 keywords, fused by interleaving (1st dense, 1st BM25, 2nd dense, ...; RRF is kept for comparison), then at most 1 chunk per card (`DEFAULT_MAX_PER_CARD`). The steps are the nodes of a datapizza `DagPipeline` (embedder → dense, bm25 → fusion → diversify), one per mode, built once. Modes `dense`, `bm25`, `hybrid` for comparisons. | Docker, key (not for BM25) |
| `rag/embedding_cache.py` | `CachedEmbedder`: saves embeddings in a `DiskCache` (`.cache/`), one entry per text, so the same text is never paid twice; works offline on cached texts. | key only for new texts |
| `evaluation/retrieval_metrics.py` | Retrieval metrics on the gold set: recall@1, recall@5, MRR@10 (course definitions) plus multi-card checks. Used by `scripts/eval_retrieval.py`. | — |
| `evaluation/judge.py` | LLM-as-judge with typed outputs via `structured_response`. Faithfulness claim by claim (RAGAS method: split the answer into statements, check each against the retrieved context with its evidence; score = supported share) or holistic (one `Verdict`, score 0–1 + reason); a one-sided answer to conflicting sources is not faithful. Relevancy to the question. Scores clamped; a judge error scores 0 with its reason. `JUDGE_OUTPUTS`: its typed answers, the ones its disk cache can rebuild. | key |
| `evaluation/gold_run.py` | The gold run: `load_gold()`, `run()` (recall@1/5 and MRR, faithfulness and relevancy, abstention out of corpus, latency p50/p95, cost), `score()` = (faith + rel) / 2, `table()`, `detail()` (rows below 0.7 marked), `REMINDER` (what to try per low metric), `replay()` to judge a saved run again. Used by `scripts/gold_run.py`. | — |
| `evaluation/cost.py` | Cost of the model calls: `TokenMeter` counts the tokens of every call made through a client (agent steps, rewrite, judges), `estimate_cost()` prices them with `PRICES` (OpenAI price list). | — |
| `evaluation/answer_checks.py` | Automatic checks on agent answers against the gold set: citations only to consulted cards, no card-internal author references as citations, grounding, tool use, "Non lo so", answer language, required facts, length of advice. Reuses the guardrails' checks, so it measures what the agent enforces. Used by `scripts/eval_agent.py`. | — |
| `guardrails/input_guard.py` | Before any model call: prompt-injection attempts, off-topic questions and questions over 2000 characters get a fixed reply (Italian or English); greetings get the presentation. The football test is a generous vocabulary check (words, stems, formations like 4-3-3 or 433, game situations: the minute, the score, the phase of the match, a man down); in a chat, follow-ups go through. | — |
| `guardrails/output_guard.py` | After the answer: language of the question, names/numbers present in the consulted cards, at least one `[card_id]` and only consulted ones. Each problem comes with a precise instruction for the one rewrite. Also parses citations for the evaluation. | — |
| `guardrails/verifier.py` | The verifier, optional and off by default (`MatchAnalyst(verify=True)`, `--verifier` in `eval_agent` and `gold_run`; measured under the acceptance gate: +0.025 faithfulness for 5x cost and 4x latency): a second model (gpt-4.1-mini) checks every statement of the answer against the consulted cards with the gold run's claim-by-claim method (`judge_faithfulness_claims`); each unsupported statement becomes an `Issue` ("correct it with what the cards say") for the output guardrail's single rewrite. Catches roles swapped between names that are all in the cards, which the deterministic checks cannot see. A failed check never blocks the answer: it is reported. | key |
| `guardrails/grounding.py` | Grounding check: every proper noun and number of an answer must appear in the consulted cards or in the question (catches facts from the model's memory); English names of countries and competitions accepted; in an English answer the Title Case words of headings and bold labels are not names, their numbers are still checked (E16). `trim_name_parts`: a name the cards write only in part ("Philipp Lahm" for "Lahm") is cut back to their words before the check (E9). | — |
| `guardrails/facts.py` | Entry point of the facts written or checked by code: the names the agent, the evaluation and the tests import, from the five modules below, and `FACT_KINDS` (the issues whose sentence is removed if it is still there after the rewrite). | — |
| `guardrails/real_case.py` | The real case of an advice answer written by code from the card. The model writes `Caso reale: [case_id]`; `expand_real_cases` gives the line the card's own sentence on that final (the line of a consulted card citing it, game situations first, else the match card's outcome); a line citing a situation card is led back to the final it names; a line about something else that cites a consulted card stays as written; a final no consulted card speaks of is removed. `collapse_real_cases` gives the checks and the rewrite the label-and-id form (E1, E2). | — |
| `guardrails/coaches.py` | `fact_issues`: coach-team pairs ("l'Atalanta di Italiano", "il PSG era allenato da Scaloni", "Pioli ... nel Milan": the team must be in the coach's card or in a final's metadata; sentences with a negation are left alone) and thresholds about a metric ("PPDA inferiore a 10" must be written in the cards) (E3, E4, E5). | — |
| `guardrails/sides.py` | `perspective_issues`: the side of a game situation (the coach "a man down", "behind" or "ahead", read from first-person phrases): the card of the mirror situation cited without the card of the coach's side goes to the rewrite, to be used only for the opponent's moves (E17); `man_down_answer`: a man down has no card, so, when the coach gave no score (`writes_man_down`: with a lead or a deficit that score's card applies), the answer is written by code (the 11 v 10 card's options as the opponent's moves, a real case from the side that was down to ten), no model call. `premise_issues`: a score the coach never gave is not taken for granted (E6). | — |
| `guardrails/additions.py` | After the review, by code (`tidy`, in this order): `effect_tails`, an effect added after a comma (", creando ...", ", evidenziando ..."), with no number or name, is cut (E20); `closing_summary`, a last sentence that sums up or evaluates with no citation is removed (not a style question's conclusion); `unmarked_unknown`, a detail said to be missing ("non specificato") in an answer that never says "Non lo so" gets those words (E19). | — |
| `guardrails/text.py` | The sentences of an answer, shared by the guardrails: `sentences` (a full stop inside a citation does not end one), `remove_sentences` (a wrong fact still there after the rewrite is taken out), `normalize` (no accents, no case). | — |
| `guardrails/language.py` | Italian or English, from function words. | — |
| `tools/corpus_tools.py` | The agent's tools. `search_cards`: up to 5 results, one per card, each headed by its `[document_id]` (the only bracketed text: card-internal references become parentheses); the first 2 are whole cards; an optional card-type filter is a preference (the best overall result is always kept). `read_card`: a whole card. Errors come back as text, never as exceptions. The descriptions state what the corpus covers. `card_context()`: whole cards as one `[card_id]` context block (used by the output guardrail's rewrite and by the judge). | as the Retriever |
| `observability/tracing.py` | Tracing to Arize Phoenix: `setup_tracing()` connects OpenTelemetry to Phoenix (off, with a message, if Phoenix is not running); the exporter translates datapizza's span attributes to OpenInference (LLM, TOOL, AGENT kinds, tokens, messages); `span()` and `record_documents()` write our own spans: the question, the guardrails, the retrieval with its chunks, the rewrite. | Phoenix (optional) |
| `observability/logs.py` | `setup_logging()`: the log of the app and the CLI, Python's `logging` written to `logs/match_analyst.log` (git-ignored, rotated at 1 MB, 5 old files). Only this project's loggers (`src.*`) write to it. INFO: new conversation, question length (not its text), input guard, searches with cards and time, output guard and rewrite, answer time/tokens/cost; WARNING: stopped questions, discarded rewrites, failed searches or saves; ERROR: exceptions with stack trace. `LOG_LEVEL` in `.env` (DEBUG adds the search queries). | — |
| `agent/analyst_agent.py` | `MatchAnalyst`: the datapizza `Agent` (client built by datapizza's `ClientFactory`: gpt-4o-mini, or the model passed as `model`) with the two tools, between the input and output guardrails (one rewrite at most, kept only if it is not worse). The rewrite puts rules + cards (`card_context()`) in the `system_prompt` and the request in the `input`. `last_guard` / `guard_note` say what the guardrails did (never silent); `guardrails=False` runs the bare agent for comparison. `stateless=False` keeps the conversation (chat); `consulted_cards` lists the cards used for the last answer. Client and retriever can be injected (tests use a scripted fake LLM). | key, Docker |
| `agent/prompts.py` | System prompt: greetings without tools (a greeting followed by a football question is a football question, E14); only what the cards say (no effect they do not state, no closing summary), "secondo X" answered from X's card only, one team's detail not given to a coach with another formation (E18); `ENGLISH_REMINDER` added to English questions; football questions always searched; answers only from passages, each claim cited with `[document_id]`; conflicts reported; "Non lo so" when the cards do not cover it. `REWRITE_REQUEST`: the message of the output guardrail. | — |
| `ui/backend.py` | The Streamlit app's backend: `Conversation` = one chat (the agent with memory, `stateless=False`) and its token meter; `ask()` returns the answer with consulted cards, searches, guardrail report and meta (time, tokens, cost, model). `make_client()` is replaced by a fake in tests. Every answer is saved by `chat_log.py`. | key, Docker |
| `ui/chat_log.py` | `ChatLog`: the app's conversations saved for analysis, one JSON Lines file per chat in `chats/` (git-ignored), one line per answer appended as soon as it is given: question, answer, consulted cards, searches, guardrails, meta, and the turns added to the agent's memory (datapizza `Memory`, tool calls and results included). `load_chat()` reads a file back, `load_memory()` rebuilds the chat's `Memory`. | — |
| `mcp_server/server.py` | The MCP server (reference SDK `mcp` ≥ 2, `MCPServer`), started by `mcp_server.py` at the root. Read-only tools: `search_cards` (the agent's `CorpusTools` on a `Retriever` built at the first search and again after a failure), `read_card` and `list_cards` (`CardLibrary`: the indexed cards read from `corpus/`, rebuilt as `Retriever.card_text` does, no Qdrant); resources `card://{document_id}` (the cards listed one by one, plus the template); prompt `prepare_match(team, opponent)`. `keep_stdout_for_the_protocol()` moves datapizza's console log off stdout, the stdio protocol channel. stdio by default, Streamable HTTP (stateless) with `MCP_HTTP=1`. | Qdrant and key for `search_cards` only |
| `ui/view.py` | Pure formatting for the app: page style (`CSS`, the `.ma-*` classes of the redesign made with Claude Design, see `design-system/`), masthead (`header_html()`), welcome tiles, numbered citation badges (`cite_badges()`, `citation_numbers()`: the same number on the badge and on the card next to the answer; model output HTML-escaped), the answer with its "Non lo so" parts boxed (`answer_html()`), the guardrail box (`guard_html()`), cards (`load_card_index()`, `card_header_html()`, `card_body()`), answer details and searches, example questions, summaries of the saved runs for the evaluation tab. | — |
| `ui/graphics/` | Graphics under a chat answer, SVG drawn by code in the design system's colours (`--ma-*`, light and dark), no chart library and no JavaScript; rendered with `st.markdown` (`st.html` strips `<svg>`). One module per graphic (`formations.py`, `shape.py`, `timeline.py`, `match_numbers.py`, `goal.py`), with `svg.py` (the pitch, the colours, the text, the style of an animation, the caption) and `badges.py` shared, and `answer.py` choosing the graphics under an answer; the package exports the names below. `formations_in` / `coach_formations`: the formations of the coach's own questions and whose they are ("noi giochiamo 4-3-3", "affrontiamo un 4-4-2", "352"; no side, no pitch); `formations_svg`: the pitch, the coach's team in red and filled, the opponent's in ink and hollow, direct labels and a tooltip per player, the players running to their place (CSS only, off with reduced motion); `team_badge`: a team's symbol, drawn by code: the flag of a national team (a public symbol, simplified), a neutral shield with the initials in the club's colours for a club (no club crest or competition logo: trademarks). `timeline_svg`: the timeline of a final (the two teams' symbols at the start of the axis), from the `timeline:` of its card (goals with the score, penalties, saves, a post, red cards, changes; extra time and the shoot-out only when played; the first team of the title above the axis in red, the other below in ink; the shape of a mark says what it is, a dashed one has no minute in the card; a tooltip with the card's own words; the axis drawn and the events appearing in match order). `answer_figures`: under an answer, the pitch when its question names a formation, a coach's change of shape when a line citing the coach's card writes the shape it becomes (`cited_shape_changes`), the timeline of the final its real-case line cites and its numbers when the question or the answer names one of them (`names_a_number`); only the newest answer animated. `shape_svg`: how a coach's team changes shape, from the `shape_changes:` of the card (Inzaghi's 3-5-2 that becomes a 5-3-2 without the ball, the 4-4-2 of Pioli's thesis that becomes a 3-4-3 in the pressing on the flanks, Guardiola's City from 3-2-5 to 2-3-5): the players moving from one shape to the other and back (CSS only), the first shape faint and hollow, the card's own words in the tooltips and the caption; who goes where is not in the cards: the least movement, easier along the flanks (`shape_moves`). `numbers_svg`: the numbers of a final from the `## Numeri` table of its card (`final_numbers`: the values as written; a value it cannot read leaves its row out), one bar per metric split between the two teams (the first of the title red and filled, the other ink and hollow), the contested possession of 2026 in a neutral with its label, the card's note on the sources that differ, PPDA read the other way in the glossary's words. `goal_svg`: the action of a goal of a final with StatsBomb data (`goal_actions`, from `references/derived/`): passes solid, carries dashed, the shot thick, drawn as the ball travels at the real tempo (faster above 14 s, and said), every player named when he touches the ball, the scorer where he shoots; `pick_goal`: the goal at a minute the real-case line writes, else the longest action. The cards tab shows a final's timeline and numbers, a coach's change of shape, and lets you pick a goal to play. | — |

`corpus/`, `evaluation/` and `guardrails/` work on text only (no network); `observability/` sends traces only when Phoenix is running; `rag/`, `tools/` and `agent/` talk to external services.
Commands that use these modules are in `scripts/` (see the main README).
